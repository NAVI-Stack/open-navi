### Design decisions

- **Sibling descriptor via a Mutation field, not an overload.** `MutationDescriptor`
  rides on a new `ActionDescriptor.Mutation` pointer so the *same* `Pipeline.Run`
  consumes it (seam §5). No fork, no second queue, no second authority.
- **Disposition ladder is the Risk CheckFunc.** Ambiguous resolution → `Modified`
  (softened Create), Merge/Deprecate/Forget → `RequiresConfirmation` + hard floor,
  Append/Reinforce/Create → `Approved`. The write-class gate lives at the
  Permissions tier so disabling it yields `Rejected` (drop, not write).
- **Embedding backend = deterministic stub.** Hermetic tests; Ollama deferred
  behind the interface. No vector index engine — only the interface + a persisted
  reference, per the frozen contract.
- **One subprocess pattern.** Extraction and resolution share a single Python
  worker invoked over the existing JSON-RPC-stdio contract; no new IPC.
- **Confident vs. uncertain merge.** The resolver reports multiple matches by a
  *deterministic* blocking key as a confident merge (→ Proposal, hard-floored);
  multiple *fuzzy/name* matches as ambiguous (→ Modified). This gives a real,
  testable Proposal path without guessing merges.
- **V1 entity targets = Contacts + Memories.** Contacts from person/email/handle/
  proper-noun candidates; an append-only Memory per promotion-candidate chunk.
  `History`/`Knowledge`/`Artifact` targets are reachable through the same seam but
  not wired in V1 (kept minimal).
- **Idempotency by derivation key.** `sha256(record, chunk, candidate, kind)` is
  the `intake_provenance` UNIQUE key; proposals also carry a stable boundary key.
  Replays skip; no duplicate entities or proposals.
