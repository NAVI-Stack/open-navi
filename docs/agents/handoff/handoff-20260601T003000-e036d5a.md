### Design decisions

- **Vector index engine = pure-Go brute-force cosine (`BruteForceIndex`).** Chosen
  over sqlite-vec or a CGO ANN library because the supported NaviD runtime (Docker
  Compose) and `make test` both build **without CGO** — the same hermetic-build
  reasoning P3 used to pick the stub embedder over local-Ollama. At the V1 target
  (10k chunks × 96-dim) a linear scan is ~1M multiply-adds/query. **No data
  migration:** the index is rebuilt on demand from the existing `intake_embeddings`
  references (the persisted reference *is* the index source). When volume outgrows a
  linear scan, an ANN engine drops in behind the `VectorIndex` interface with no
  caller change.
- **Measured retrieval latency (10k chunks):** `BenchmarkRetrieve10kChunks` ≈
  **119 ms/op** on an Intel Core Ultra 9 285K (in-memory SQLite). The cost is
  dominated by loading + JSON-decoding all 10k stored vectors per call (the index is
  rebuilt each query, not cached) plus the entity-graph `SearchContacts` lookups;
  the cosine scan itself is sub-millisecond. This is comfortably below the latency
  floor of the LLM call it precedes. **Obvious next optimization:** cache the built
  index / store vectors as blobs instead of JSON.
- **Privacy enforcement lives at the `ModelSelector` boundary.** `SelectWithPrivacy`
  applies the privacy tier as a filter before the existing TaskClass selection:
  cloud-eligible → delegate to `Select` unchanged; otherwise restrict to local
  models and re-select, returning a typed `RouteRefusedError` if none can serve
  (e.g. tools required but no tool-capable local model). The refusal is observable
  and tested; no cloud provider is ever selected for `secret`-in-Local. This is the
  route-choice seam — the live ICS router consumes the selector, so enforcement at
  this layer governs every route. The retrieved-set's `MaxPrivacyClass` is the input
  that makes the coupling concrete (exercised in the e2e).
- **Contextualize injection = a Facts block**, mirroring the existing `FactsBlock`
  path in `runtimeContextAssembleInput` (which has the current user message as the
  query). Nil retriever or empty return → no Facts item → identical turn-time
  behavior. The `external_untrusted` label is preserved into the block and
  quote-wrapped.
- **One distillation primitive, two call sites.** `intake.IngestDistillFn` and
  `retrieve.DistillFn` both alias `distill.Distill`; a test compares all three
  function pointers. Retrieval distillation stays extractive (P2's abstractive hook
  remains interface-only) so the retrieval path makes **no LLM calls**.

## What was not done

- **Live ICS router privacy wiring.** Privacy enforcement is implemented and tested
  at the `ModelSelector` boundary and surfaced via the API; threading the retrieved
  set's `MaxPrivacyClass` into the live `applyRoutingToCanonicalRequest` →
  `RouteRequest` path was deliberately **not** done — that router is a large, mature
  surface and the frozen contract says "do not rebuild the contextual router." The
  enforcement logic, typed refusal, and policy view are real; the live wire is a
  thin future hookup (set `ModelSelector.PrivacyMode` from preferences and pass the
  effective class when a route request carries retrieved context).
- **Embedding-vector caching / blob storage.** Embeddings are still JSON in
  `intake_embeddings` and the index is rebuilt per query (see latency note). Fine
  for V1; the first thing to optimize if retrieval volume grows.
- **Ollama embedding backend** — still interface-only (inherited from P3); retrieval
  uses the same stub embedder synthesis persisted with, so the vector spaces match.
- **`-race` run** — this host has no gcc/cgo, so the race detector is unavailable
  (unchanged from P3). P4's retrieval path is synchronous and read-only; it adds no
  new concurrency.
- **Console surfaces, Vault retrieval, query-time Python NER** — out of scope (P5 /
  parallel / not required for V1), untouched.
