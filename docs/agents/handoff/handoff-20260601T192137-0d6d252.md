## What was done

### New package `internal/vault/`

- **`projector/projector.go`** — idempotent entity → Markdown rendering (YAML
  frontmatter + body) and a tolerant `Parse` back to a `Doc`. Frontmatter has a
  marker comment delineating projector-managed fields (`navi_entity_id`,
  `navi_entity_type`, `navi_confidence`, `navi_created_at`, `navi_updated_at`,
  `navi_provenance`) from owner-editable ones (`navi_kind`/`navi_category`/… and
  `navi_forget`). Deterministic hand-built frontmatter → byte-stable output
  (`Render` is pure). `DefaultPath` implements the §8 layout
  (`contacts/`, `knowledge/<topic>/`, `memories/YYYY/MM/`, `artifacts/`). No
  editor lock-in — plain YAML + Markdown.
- **`projector/index.go`** — read-only generated index pages under `_index/`
  (`contacts-by-recency`, `knowledge-by-topic`), tagged `navi_readonly: true`;
  `IsIndexPath` lets the worker ignore edits to them.
- **`diff/diff.go`** — owner-edited `Doc` vs current entity snapshot →
  `[]governor.MutationDescriptor` (`Source = "vault"`, `Trust = owner`,
  `VaultPath` provenance). Routine attribute edits collapse to one Reinforce;
  `navi_forget: true` → Forget; `navi_entity_id` swap → Merge; file delete →
  `ForgetOnDelete`. Structural intent is always a hard-floored **request**.
- **`watcher/watcher.go`** — fsnotify watcher with a **debounce** window
  (default 750ms, configurable) and a **mute** window the worker brackets around
  every projector write so reprojection never re-enters as a fake owner edit.
- **`worker.go`** — orchestration: `ProjectAll` (idempotent, skips unchanged
  files), `Start` (project → watch → drift ticker), `handleWritten`/`handleRemoved`,
  `runMutations` (→ `governor.EvaluateMutation` → write / Proposal / drop / softened),
  `ReprojectEntity` (the hook for *any* synthesis caller), `DriftSweep`, and the
  privacy gate (`maybeCloudEmbed` / `CloudReachAllowed` via `llm.CloudEligible`).
- **`entities.go`** — concrete-type ↔ `projector.Entity`/`diff.Current` converters
  for Contacts, Knowledge (facts), Memories, Artifacts; approved-edit writers; and
  `recordOwnerOverride` (confidence bump + "overridden by owner" mutation-history
  note for §11 conflict handling).
- **`util.go`** — small helpers.

### Store (raw SQL, no ORM)

- **`vault_state.go`** + new `vault_state` table (additive DDL in `db.go`):
  file ↔ entity mapping + last-projected content hash for drift detection and

- **`vault_sources.go`** — read-only `ListAllFacts` / `ListAllMemories` /

### Governor (additive, non-breaking)

## What was not done

- **Event-driven reprojection for external/Deep-Reflection writes.** Owner-edit
  approved writes reproject **inline**; the public `Worker.ReprojectEntity` hook
  exists for other synthesis callers, but there is no bus event emitted by
  `internal/intake/synthesize` today, so external-delta reprojection is currently
  carried by the **periodic drift sweep** (default daily), which regenerates every
  file from canonical state. Wiring synthesize to call `ReprojectEntity` (or emit
  an event the Vault subscribes to) is a thin, additive follow-up. Tested via
  `TestDriftSweep_RegeneratesDivergedFile` (external `SaveContact` → sweep → file
  regenerated).
- **Native per-entity privacy class.** World Model entities (Contact/Fact/Memory/
  Artifact) do not store a privacy class natively; the Vault defaults edits to
  `personal` with an owner override via a `navi_privacy` frontmatter attr. The
  enforcement seam (`maybeCloudEmbed` gated by `llm.CloudEligible`) is real and
  tested; in production `CloudEmbedder` is nil (local heuristic embedder), so
  secret-in-Local is trivially safe.
- **Knowledge/Memory/Artifact owner-create from a brand-new file.** V1 ingests
  edits to *projected* files (resolved via `vault_state` or `navi_entity_id`);
  a hand-authored unmapped file is logged and ignored (no silent entity create).
- **Artifact body editing.** The Vault projects Artifact **metadata** + a link to
  the Artifact System body (per spec); only display-title/description round-trip.
- **`-race`** — host has no cgo (unchanged from P3–P5). The Vault's only
  concurrency is the watcher debounce/mute maps, each mutex-guarded.

## Notes for next agent

- **Hard invariants to keep green:** `TestNoWorldModelWritesBypassSeam_Forget` /
  `_Disabled` (no Vault write bypasses `governor.EvaluateMutation`),
  `TestHardFloor_ForgetNeverAutoApproved` (autonomy cannot break the floor),
  `TestProjectAll_Idempotent` / `TestOwnerEdit_ApprovedRoundTrip` (byte-stable
  reprojection), and the P1–P5 isolation tests (`TestOnlySynthesizeWritesWorldModel`,
  `TestRetrievalIsReadOnly`, `TestNoWorldModelWritesOnPolicyChange`).
- **One queue, one seam.** Vault Proposals use `source_process: "vault"` in the
  existing queue — do not add a second queue. Every owner edit becomes a
  `MutationDescriptor` passed to `governor.EvaluateMutation`; do not add a direct
  World-Model write path from the Vault.
- **Structural intent is a request.** File delete / `navi_forget` / `entity_id`
  swap raise hard-floored Proposals; they never mutate truth directly.
- **Idempotency contract.** `projector.Render` must stay a pure function of its
  `Entity`. The drift sweep and the echo guard both depend on
  `projector.ContentHash` being stable for identical entity state.
- The `vault_state` table is rebuildable bookkeeping (file↔entity↔hash), never
  authority; a wipe is recovered by the next `ProjectAll`/drift sweep.
