# @navi/ui

The shared **NAVI UI Library**: design tokens, primitives, theming, interaction
patterns, and a pluggable **generative-UI** runtime. It is the single source of
truth for the NAVI design system across the ecosystem. The **NAVI Console** is
its first consumer and proving ground.

> Status: **M2 (library hardening + OpenUI adapter)**. Ships a standalone built
> artifact (`dist/`) for external consumers while in-repo apps still consume
> source — see [`docs/architecture/navi-ui-library.md`](../../../docs/architecture/navi-ui-library.md).

## Install / consume

**In-repo** the package is wired through the `web-src/` pnpm workspace and a
Vite/TS alias, so apps import it **as source** (instant HMR, one type-check, no
build-order coupling):

```ts
import { Button, Card, Stack, Text, StatusBadge, Field, EmptyState, Spinner } from '@navi/ui';
import { ToastProvider, useToast, ConfirmProvider, useConfirm, Dialog } from '@navi/ui';
import { applyTheme, ThemeProvider, type ThemeModel } from '@navi/ui';        // or '@navi/ui/theme'
import { GenUI, naviSpecEngine, createOpenUIEngine } from '@navi/ui';          // or '@navi/ui/genui'
import '@navi/ui/tokens.css';                                                  // design tokens
```

**External** NAVI apps consume the built artifact via the package `exports` map:

```ts
import { Button, GenUI } from '@navi/ui';      // → dist/index.js (+ dist/index.d.ts)
import '@navi/ui/tokens.css';                  // → dist/tokens.css (design tokens)
import '@navi/ui/navi-ui.css';                 // → dist/navi-ui.css (component styles)
import { createNaviOpenUIEngine } from '@navi/ui/openui';  // opt-in OpenUI integration
```

`react`, `react-dom`, `react-aria-components`, and `lucide-react` are
**peer dependencies** (you bring your own); `clsx` and `zod` are bundled.

## What's inside

| Area | Exports |
|------|---------|
| **tokens** | `tokens.css` — ~140 `--navi-*` CSS custom properties (surfaces, text, accent, status, spacing, radius, typography, motion, z-index). |
| **theme** | `ThemeModel`, `applyTheme`, `ThemeProvider`/`useTheme`, `createDefaultTheme`, `normalizeTheme`, `contrastRatio`, light/dark token groups, density + font scaling. |
| **primitives** | `Button`, `Card`, `StatusBadge`, `EmptyState`, `Stack`, `Text`, `Spinner`, `Field`. Accessible (built on `react-aria-components`), token-styled via CSS Modules. |
| **patterns** | `Dialog` (generic modal), `ToastProvider`/`useToast`, `ConfirmProvider`/`useConfirm`. |
| **genui** | `GenUI`, `naviSpecEngine`, `createOpenUIEngine`, `defaultRegistry`, `extendRegistry`, `naviUINodeSchema`, `naviUIVocabularyPrompt`, streaming helpers. |
| **openui** (`@navi/ui/openui`) | `createNaviOpenUIEngine`, `createNaviOpenUIAdapter`, `mapOpenUIElement`, `naviOpenUISchema`, `naviOpenUISystemPrompt`. Requires the optional peer `@openuidev/react-lang`. |

## Generative UI

NAVI (or any LLM) emits a **NAVI UI Spec** — a compact, safe JSON tree — which
`<GenUI>` validates and renders with `@navi/ui` primitives:

```tsx
<GenUI
  source={{ t: 'card', title: 'Hi', children: [{ t: 'text', value: 'Generated by NAVI' }] }}
  onAction={(action) => console.log(action.intent, action.params)}
/>
```

Specs are **declarative and safe**: no embedded code or raw HTML. Interactivity
is expressed as named `action` intents that the host app wires up.

### Streaming / progressive rendering

Generative UI arrives token-by-token. Pass `streaming` and `<GenUI>` renders the
**valid prefix** of an incomplete spec, keeping the last good tree so a mid-stream
parse miss never flashes an error:

```tsx
<GenUI source={partialSpecSoFar} streaming />
```

Engines opt in by implementing `parsePartial` (the native engine repairs
truncated JSON; the OpenUI engine uses OpenUI's incremental parser).

### OpenUI Lang (opt-in)

[thesysdev/openui](https://github.com/thesysdev/openui) plugs in behind the same
`GenUIEngine` interface. The `@navi/ui/openui` subpath ships a concrete adapter
that parses **OpenUI Lang** and renders it through the **same** NAVI primitives:

```tsx
import { GenUI } from '@navi/ui';
import { createNaviOpenUIEngine } from '@navi/ui/openui';   // needs @openuidev/react-lang

<GenUI engine={createNaviOpenUIEngine()} source={openUILangText} streaming />;
```

The **core** library takes no dependency on `@openuidev/*` — the adapter lives in
an opt-in subpath (`@openuidev/react-lang` is an `optionalDependency`), so apps
that don't use OpenUI pay nothing.

### Extending the registry

Apps add or override node renderers without forking the design system:

```ts
import { extendRegistry, defaultRegistry } from '@navi/ui';
const registry = extendRegistry(defaultRegistry, { markdown: ({ node }) => <MyMarkdown source={node.value} /> });
```

## Scripts

```bash
pnpm run typecheck    # tsc --noEmit
pnpm run test         # vitest
pnpm run build        # standalone library build → dist/ (vite.lib.config.ts)
pnpm run smoke:dist   # import + typecheck the built dist artifact
pnpm run ladle        # component workbench (stories + axe a11y) at :61000
pnpm run ladle:build  # static Ladle build
```
